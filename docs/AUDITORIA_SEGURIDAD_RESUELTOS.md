# Auditoría de seguridad: hallazgos del frontend resueltos

Base: `AUDITORIA_SEGURIDAD_GENERAL.md` (2026-11-04, repo `adminprop-repo-files`). Rama `fix/auditoria-seguridad-frontend`. Acá sólo figuran los hallazgos que tocan este repo; los del backend, legales y de proceso quedan fuera salvo que dependan del frontend.

## Variable nueva a cargar en Doppler

| Variable                  | Dónde                                          | Valor                                                                                                                                                      |
| ------------------------- | ---------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `SITES_REVALIDATE_SECRET` | proyecto `admin-prop`, configs de `apps/sites` | **Exactamente el mismo valor** que ya tiene el backend en `SITES_REVALIDATE_SECRET` (el backend usa una única variable para el throttle y para revalidar). |

- Ya existía para `/api/revalidate` de `apps/sites`; ahora además se manda como `X-Sites-Secret` en las lecturas server-side a la API (A-6). Si ya está cargada en `sites`, no hay nada nuevo que crear.
- Solo servidor. **Nunca** `NEXT_PUBLIC_*`.
- Sin la variable, el sitio funciona igual pero vuelve a compartir el cupo por IP (comportamiento anterior).
- Recomendación pendiente (backend): usar un secreto distinto para el throttle y para revalidar.
